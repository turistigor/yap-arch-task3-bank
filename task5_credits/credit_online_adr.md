Логика принятия решений:
- Функционал работы с кредитами планируется добавить и перенести в новый сервис, включая миграцию имеющихся данных.
- Есть проблемы с АБС:
    - она сосредоточила в себе много функций, при этом уже есть сложности с производительностью;
    - технологии при помощи которых реализована АБС создают риск потери поддержки;
- Новый сервис планируется реализовать с использованием знакомых командам технологий: Java/С#, React, MS SQL/Oracle. Вариативность обусловлена неочевидностью исполнителей, которые будут определены в зависимости от уровня нагрузки.
- Вынос функционала кредитов в отдельный сервис решает все проблемы со скоростью обработки заявок, связанные с суточными периодами синхронизации баз разных систем так как работает за счет прямых вызовов.
- Информацию о ставках планируется хранить в БД нового сервиса.
- Вспомогательная информация для расчета ставок получается автоматически из других систем через API-вызовы (это возможно по условиям задачи) и доступна для использования кредитным менеджером.
- Работу с предодобренными заявками планируется реализовать в новом сервисе кредитов. Это позволяет решить потенциальные проблемы с дублированием предодобренных заявок за счет автоматического сопоставления заявок с имеющимися по идентификаторам клиента.
- Одинаковость отображаемой информации по ставкам в разных местах обеспечивается единственностью источника - новый сервис кредитов.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Альтернативные варианты предусматривают управление нагрузкой на разработку и управление рисками.

- Консервативное решение: реализовать все операции с депозитами в АБС. Оно позволяет снизить сложность разработки MVP, однако несет в себе риски перегрузки систем и сложности реализации годового плана.

- Максимальное решение: обновление ИТ-структуры для динамичного развития в будущем. Помимо нововведений из основном варианта, включает внедрение Event Driven подхода на основе Kafka. Этот вариант позволяет снизить зависимость между сервисами, упростив разработку, обновление и развертывание.

### <a name="_bqtru6e2h5dx"></a>**Недостатки, ограничения, риски**
Недостатки:
- Менеджерам кредитного отдела бэк-офиса и фронт-офиса придется научиться работать в новом интерфейсе сервиса депозитов.
- Высокая сложность разработки из-за старта нового сервиса кредитов и переноса в него соответствующего функционала из АБС (включая миграцию данных).

Ограничения:
- Для межсервисных взаимодействий осознанно не использованы брокеры сообщений с целью снизить сложность и без того непростой разработки. Взаимодействия между сервисами происходит при помощи синхронные технологии (HTTP/GRPC), что ограничивает транзакционность, усиливает связи между сервисами.

Риски:
- Ошибки при переносе функционала и данных работы с депозитами из АБС в новый сервис.
